# 예매 탐색 시간 구간 설계

## 목표

SRT 조회 기준 시각과 별개로 예매 탐색 대상 열차의 출발시각 시작·끝을 분 단위로 지정한다. `15:00~17:00`이면 두 경계를 포함해 해당 구간의 열차만 좌석 및 예약대기 대상으로 검사한다.

## 인터페이스와 기본값

- CLI는 기존 `--target-time HH:mm`과 새 `--target-end-time HH:mm`을 사용한다.
- UI `Config`와 `/start` 요청에 `targetEndTime: string`을 추가하고 시작·끝 입력을 나란히 표시한다.
- 끝 시각을 생략하거나 기존 저장 설정에 값이 없으면 `23:59`를 사용해 기존의 “시작 이후 전부” 동작을 유지한다.
- 실행 배너, 탐색 로그, 예약 및 예약대기 알림은 `탐색 15:00~17:00` 형식으로 표시한다.

## 검증과 자동 보정

- 시작과 끝은 모두 유효한 `HH:mm`이어야 한다.
- `조회 기준 시각 ≤ 탐색 시작 시각 ≤ 탐색 끝 시각`이어야 한다.
- UI에서 조회 기준 시각을 늦춰 시작이 자동으로 올라갈 때, 끝이 새 시작보다 빠르면 끝도 새 시작과 같은 시각으로 올린다.
- UI에서 시작 시각만 직접 변경해 끝보다 늦어지면 자동 보정하지 않고 시작 버튼에서 명확한 검증 오류를 표시한다.

## 열차 선택과 테스트

- `SeatSelectOpts`에 최대 출발시각을 추가하고 출발시각이 `[시작, 끝]` 범위인 행만 좌석 검사와 후보 수 계산에 포함한다.
- 시작 경계 포함, 끝 경계 포함, 끝 이후 제외, 범위 내 가장 이른 잔여석, 후보 수, 예약대기 우선순위, 빈 범위를 브라우저 테스트로 검증한다.
- CLI 기본값과 시각 순서, UI 저장값 마이그레이션·자동 보정·검증, UI에서 CLI로 끝 시각 전달을 단위 테스트로 검증한다.
- README와 UI 프로덕션 자산을 갱신하고 단위 테스트, 브라우저 테스트, TypeScript 검사, UI 빌드를 실행한다.
